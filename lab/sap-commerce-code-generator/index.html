The Problem

OCC controllers and ImpEx scripts are repetitive to write by hand, and small mistakes (path variables that do not match, rows that do not match the header, undefined macros) are easy to make and slow to find.

How It Works

  1. OCC Controller Generator & Tester: configure a controller and its endpoints for SAP Commerce 2205 or 2211 and generate Spring MVC controller scaffolding, with an optional DTO, facade and validator. Try requests against a built-in mock tester that never runs Java.
  2. ImpEx Generator: build a script from a header, macros and a data grid, or import CSV/TSV, and get deterministic ImpEx text.
  3. Both tools run diagnostics (Error / Warning / Information) as you edit; errors disable export. Configurations can be saved locally and exported as JSON.

Technically Interesting

Both tools are pure TypeScript functions running in the browser. Output is deterministic (fixed ordering, no timestamps), and the 2205 and 2211 profiles differ only where it was verified (Swagger v1 versus OpenAPI v3 annotations).

Why It Matters

It removes boilerplate from two everyday SAP Commerce tasks while keeping the developer in control of what gets written to a real system.

Scope & honesty. Output is scaffolding: static checks cannot prove the code compiles or the ImpEx type, attribute or catalog exists in your installation. The mock tester is a simulation. There is no backend, no SAP connection and no AI call; nothing you type leaves the browser. This portfolio links to the app and does not embed it.
